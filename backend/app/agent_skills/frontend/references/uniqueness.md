# Uniqueness — анти-стандартизация

Скилл учит **как делать правильно**, не **как всем одинаково**.

## Закон

Каждый бриф = свой продукт. Два разных юзера **не должны** получить один и тот же layout/палитру/копирайт/набор секций.

**Эталоны** (`good_landing_sto`, `good_app`, templates) = планка качества и рабочие потоки.  
**Не** бренд, не CSS-классы, не обязательная сетка «как в примере».

## Делай

1. В ## Мышлении зафиксируй UNIQUE брифа: бренд, ниша, тон, 1 signature-якорь, палитра отрасли, 3 отличия от «типового AI-лендинга».
2. Архитектура под задачу: кофейня ≠ СТО ≠ SaaS ≠ магазин. Секции и IA из брифа.
3. Визуал: свой type + color system. Запрет копировать amber/asphalt СТО, если бриф другой.
4. Копирайт только из фактов брифа (цены, адрес, SKU, оффер).

## Бан

- Клон эталона с заменой названия
- Одинаковые hero/услуги/отзывы у разных брендов
- Навязать `.vitrine` / `.top__nav` / янтарь СТО не-авто брифу
- «Все лендинги sticky + Georgia + 7 section» как догма — это **минимум качества**, не визуальный штамп

## Gate mindset

FAIL за: пустоту, битые ассеты, фейк-форму, AI-purple, egg-copy, отсутствие уникальности брифа.  
НЕ FAIL за: другой каркас секций, другую типографику, другой ритм — если продукт читается и shippable.

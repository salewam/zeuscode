## Вердикт простыми словами

**Связка из 3 работает и собирает цельный сайт.**  
Но **в ~13 раз дороже и в ~3.5 раза медленнее**, чем одна Gemini Pro на том же ТЗ.

Где связка реально помогла:
- Judge заметил, что у агентов HTML **обрезался по лимиту длины**, и собрал **цельный** финальный файл.
- Шрифты/ссылки чистые (в solo Gemini сломал Google Fonts markdown-ссылками `[url](url)` — шрифты не подтянутся).
- Чище структура, нормальный brand-first hero.

Где связка не дала «вау»:
- Оба варианта без реальных фото (только градиенты) — для автосервиса слабо.
- Много карточек-услуг (типичный AI-лендинг).
- Форма — `alert()`, не настоящая запись.
- Визуально оба «асфальт + янтарь», разница не космическая для простого лендинга.

## Чего не хватает системе (по этому тесту)

1. **Лимит длины ответа агентов** на UI-задачах → битый HTML до judge. Нужен режим «сайт»: chunk/файл или больший max_tokens на panel.
2. **Визуальный якорь** — skill/политика «обязательно живые фото / не один градиент».
3. **Пост-проверка HTML** перед отдачей клиенту: валидные `<link href>`, закрытые теги, нет markdown-мусора в HTML.
4. **Соотношение цена/польза** для простых лендингов: auto не должен всегда уходить в FULL/power-3, если CASCADE/1 сильная модель хватает.
5. **Реальная форма** (хотя бы POST заглушка / publish booking), иначе сайт «для галочки».
6. В Cursor пользователь не видит path/cost — владельцу ок (usage log), юзеру нет прозрачности «почему долго/дорого».

## Рекомендация

- Для **простого лендинга**: 1 сильная модель (или CASCADE) часто достаточно → дешевле/быстрее.
- Для **сложных UI / когда 1 модель ломает HTML**: FULL/power окупается за счёт judge-сборки.
- Следующий тест: тот же сайт с требованием «3 реальных фото + без карточек в hero» и сравнить снова; плюс solo `claude-opus-4-8` vs fusion (fairer, тот же leader).
